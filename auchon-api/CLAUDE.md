# auchon-api

Sync point and backup for Auchon's home inventory: receives the commands the offline PWA queued
and serves the changes since a cursor.

## Project

### Bounded contexts

- **`inventory/`**: what is stored where. Two aggregates:
  - `Location`: a place (Basement, Garage…, the root) or a nested area/container
    (shelf, box). Referenced by `Item` by id only
  - `Item`: something stored in a location, with a quantity changed by deltas

### Stack

- Go: 1.27
- Router: go-chi/chi/v5
- Database: SQLite via modernc.org/sqlite (pure Go, no CGO)
- Auth: none (single user, home network)
- Messaging: none. Events are recorded and stored in `domain_events`, nothing consumes them yet
- Migrations: pressly/goose, embedded SQL, applied on startup
- IDs: UUIDv7, generated by the client

### Kernel

The symbols this repo uses for each capability in `go/shared-kernel.md`:

| Capability | Symbol |
|---|---|
| Event recorder / base event | `event.Recorder` / `event.Base` (`lib/event`) |
| Event publisher | `event.Publisher` port; `event.NewStore(conn)` writes `domain_events` (`lib/event`) |
| Base domain error / categories | `errors.Base`; `IsNotFound()`, `IsValidationError()`, `IsNoAccess()`, `IsUnauthorized()`, `IsDuplicate()` (`lib/errors`) |
| Error → status mapper | `errors.HTTPStatus(err)` |
| Request user | n/a (no auth) |
| Command bus / query bus | `command.Bus` / `query.Bus` (`lib/command`, `lib/query`) |
| Clock | `clock.Clock` (`lib/clock`) |
| Logger | `*slog.Logger` via `lib/logger` |
| Test kit (clock stub, event spy, command spy, assertions) | `clock.NewStub()`, `test.NewEventPublisherSpy()`, `test.NewCommandBusSpy()`, `test.AssertNoError`, `test.AssertErrorIsOfType[T]` (`lib/test`) |

### Commands

- Build: `go build -o bin/auchon ./cmd/auchon`
- All tests: `go test ./...`
- Fast tests: `go test -short ./...` (everything runs on temp SQLite files; no Docker needed)
- Regenerate BDD skeleton: `go run github.com/hedhyw/gherkingen/v4/cmd/gherkingen -go-parallel=false internal/<context>/acceptance/<feature>.feature`
- Migrate: automatic on startup
- Binaries: `cmd/auchon`, which serves the API (`/api/*`) and the built web app

### Decisions

- ADRs in `docs/adr/`:
  - 0001: offline sync with a command outbox and a change-sequence pull
  - 0002: SQLite, migrations applied on startup

### Repo-specific rules

- **TDD, tests shown first**: feature scenarios and unit tests are written, run red and shown
  for approval before any implementation
- BDD uses **gherkingen** (generates `_test.go` skeletons from `.feature` files), not gocuke.
  Steps drive the real router against a temp SQLite file
- Migrations run on startup instead of in a separate step: one binary on a home server, no
  rolling deploys (ADR-0002)
- Commands arrive through the sync controller (`POST /api/sync/push`), which maps each envelope
  to its command and dispatches it on the bus. Every command must be idempotent by `commandId`
- Quantities change by delta, never by "set to N", so offline edits merge
- Commit messages: conventional commits (`feat:`, `fix:`, `test:`, `refactor:`, `docs:`, …)
